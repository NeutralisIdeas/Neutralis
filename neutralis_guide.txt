Welcome to Neutralis — a high-performance, stack-based scripting language. 
Neutralis v2.0.3 is a state-of-the-art Register-based Virtual Machine. 
Unlike traditional stack-based VMs (like Python or early Lua), Neutralis 
minimizes memory traffic by performing operations directly on virtual 
registers. This architecture, combined with Hidden Classes (Shapes) 
and a Zero-Allocation Standard Library, allows for near-native performance 
in compute-heavy scenarios such as game physics and logic.

Memory Architecture: Non-compacting Mark-Sweep GC with Global String Interning.

===============================================================================
I. CORE CONCEPTS AND PHILOSOPHY
===============================================================================

* CASE-INSENSITIVITY: Neutralis does not care about character case. 
  `PLAYER_HP` and `player_hp` are the same.
* BLOCK STRUCTURE: Blocks use `do` ... `end`.
  The keyword `eofl` must appear exactly once at the end of your script.
* REGISTERS: Each function has access to 256 local registers. The compiler 
  maps your local variables to these registers automatically.
* INDICES: Tuples use 1-based indexing (`t[1.0]`). Strings use 0-based 
  indexing for `str_sub`.

===============================================================================
II. PERFORMANCE PILLARS (HOW TO WRITE FAST CODE)
===============================================================================

1. PROPERTY ACCESS (SHAPES/HIDDEN CLASSES)
   Neutralis uses "Shapes" to optimize dictionary access. When you write 
   `player.hp`, the VM memorizes where `hp` is located in memory.
   - ALWAYS USE: `obj.property` for fixed keys.
   - AVOID: `obj["property"]` unless the key is truly dynamic. Index access 
     bypasses the Inline Cache and triggers a slower search.

2. STRING INTERNING
   All strings in Neutralis are "interned". This means there is only one 
   copy of the string "hello" in memory, no matter how many times it appears.
   - BENEFIT: Comparing two strings (`str1 == str2`) is as fast as 
     comparing two numbers because the VM just compares their memory addresses.
   - CAVEAT: Strings are immutable. Creating a new string from two others 
     is expensive.

3. THE BUFFER PATTERN
   For heavy string building (UI, logs, JSON), NEVER use `+`.
   - BAD:  `s = s + "data"` (allocates a new string every time).
   - GOOD: Use `buffer` and `buf_write`. This writes data directly into 
     pre-allocated memory.

4. VEC2 LITERALS
   Neutralis supports ultra-fast vector literals.
   - `pos = 10.0 20.0` is compiled into a single instruction. It is much 
     faster than calling `vec2(10.0, 20.0)`.

===============================================================================
III. PRIMITIVE DATA TYPES
===============================================================================

1. FLOAT: 64-bit double precision (NaN Boxed).
2. BOOLEAN: `true` / `false`.
3. NIL: The absence of a value.
4. STRING: Interned character sequences.
5. VEC2: Native 2D vector object (optimized for physics).
6. TUPLE: Dynamic array (1-indexed).
7. DICT: Key-value map with Hidden Class optimization.
8. BUFFER: Growable memory block for string processing.

===============================================================================
IV. ADVANCED SCOPING AND FUNCTIONS
===============================================================================

Variables are global by default unless they are parameters or defined 
within a loop. However, the compiler optimizes local register usage 
within function blocks.

Function Definition:
    my_func(a, b) do
        res = (a * a) + (b * b)
        return res
    end

Closures:
    Native hooks can capture C++ context, but within Neutralis, functions 
    are first-class citizens. You can pass them as arguments.

===============================================================================
V. THE ECS CHAINING SYNTAX
===============================================================================

Neutralis provides a unique "Chaining" operator `+` specifically for 
Entity-Component Systems.

    # This syntax allows for extremely readable entity configuration
    player = create()
    player + set_pos(0.0 0.0) + set_hp(100.0) + add_tag("hero")

This works because `+` on a number (entity ID) and a tuple (command) 
executes the command and returns the entity ID for the next link.

VIII. NEW IN VERSION 2.0.3 (THE LINTER & ITERATORS)
===============================================================================

1. PANIC MODE & MULTI-ERROR REPORTING
   The parser no longer dies after the first typo. It uses a synchronization 
   mechanism to "skip" broken code and find subsequent errors.
   - FEATURE: "Context Stack" tells you exactly where the error happened.
     Example: `[Syntax Error] ... in context: for loop -> block -> expression`.

2. HARDWARE ITERATORS (for-in)
   Version 2.0.3 introduces the `OP_ITER` instruction. It is up to 4x faster 
   than manual indexing.
   
   Syntax:
       my_list = tuple("A", "B", "C")
       for item in my_list do
           print(item)
       end
   
   Supported types: Tuples and Strings.

3. NATIVE ASSERTIONS
   `assert()` is no longer a slow function call. It is a VM OpCode.
   Validation in libraries is now practically free.
   
   Example:
       divide(a, b) do
           assert(b != 0.0, "Zero division attempt!")
           return a / b
       end

4. STATIC ANALYSIS (THE LINTER)
   The compiler now enforces performance best practices:
   
   - STRING CONCAT ERROR: Using `+` with strings inside any loop triggers 
     a Compiler Error. You MUST use `buffer`.
   - DICT EFFICIENCY WARNING: Using `obj["prop"]` with a constant string 
     triggers a Warning. The compiler suggests `obj.prop` for Shape optimization.
   - REGISTER OVERFLOW: If a function uses more than 256 variables/temporaries, 
     compilation fails before the VM even starts.

5. ZERO-DIVISION PROTECTION
   - Compile-time: `x = 1 / 0` triggers a Constant Folding error.
   - Runtime: Dynamic zero division throws a clean "Division by zero" 
     exception with a line number instead of crashing the process.

IX. DEBUGGER & SOURCE MAPPING
===============================================================================

Neutralis now maintains a complete Source Map. Every OpCode is linked to a 
line number in the `.neu` file.

Runtime errors now provide a full trace:
`Runtime Error at line 42: Unknown command 'pint' (did you mean 'print'?)`

Debugger support:
The VM now supports hardware breakpoints. When an instruction offset is 
added to the `breakpoints` set, the VM automatically enters a `pause()` state.

XI. PERFORMANCE BENCHMARK (v2.0.3 REFERENCE)
===============================================================================

As of version 2.0.3, Neutralis achieves the following metrics on a standard 
N^2 physics stress test (400 entities, 160,000 interaction checks):

* Total VM Execution Time: ~314 ms
* Effective Throughput: ~35 MIPS (Million Instructions Per Second)
* Instruction Latency (Avg):
    - OP_MOVE / OP_ADD: 0.022 us
    - OP_GET_PROPERTY:  0.023 us (Shape Optimized)
    - OP_CALL:          0.470 us (Heavy)

Key takeaway: The VM is highly efficient at math and property access. 
The current bottleneck is Global Variable lookup.

XIII. VIRTUAL MACHINE SPECIFICATIONS
===============================================================================

Loops are highly optimized. Neutralis supports `while` and a unique `for`.

WHILE Loop Example:
    i = 0.0
    while i < 10.0 do
        i = i + 1.0
        if i == 5.0 do continue end  # Skip 5
        if i == 8.0 do break end     # Stop at 8
        print("Counter: ", i)
    end

FOR Loop Example:
The FOR loop in Neutralis is slightly different from C. It requires a 
comparison operator in its header.

    # This loop starts at 1, goes up to 10 inclusive, increments by 1
    for i = 1.0 <= 10.0 do
        print("Iteration: ", i)
    end

    # Downward loop
    for k = 10.0 >= 0.0 do
        print("Countdown: ", k)
    end

IV. FUNCTIONS AND SCOPE

Neutralis supports multi-line functions and concise one-liners.

Block Function:
    calculate_hypotenuse(a, b) do

    end

Inline Function (The "Fat Arrow" equivalent):

        return n * factorial(n - 1.0)
    end

Unpacking Multi-return:
    get_stats() do
        return tuple(100.0, "Legendary", true)
    end

    hp, rank, is_alive = get_stats()

V. DATA STRUCTURES (TUPLES, DICTS, BUFFERS)
===============================================================================

1. TUPLES (Arrays)
   Tuples are dynamic lists. 
   IMPORTANT: Indexing starts at 1.0!

    inventory = tuple("Sword", "Shield", "Potion")
    print(inventory[1.0]) # Prints Sword
    
    push(inventory, "Bow")
    print("Items: ", len(inventory)) # Prints 4.0
    
    item = pop(inventory) # item is "Bow"

2. DICTIONARIES (Hidden Class Objects)
   Dicts are key-value maps. They use "Shapes" for optimization.
   Always use Dot-Access (`obj.prop`) for maximum speed.

    monster = dict()
    monster.hp = 250.0
    monster.name = "Orc"
    
    # Dynamic access via brackets
    key = "hp"
    print(monster[key]) # Prints 250.0
    
    # Helper functions
    if has_prop(monster, "mana") do
        print("It has mana!")
    else do
        monster.mana = 50.0
    end
    
    del_prop(monster, "name")
    clean(monster) # Instantly clears all fields without GC pressure

3. BUFFERS (High-Load String processing)
   Standard string concatenation (`+`) creates a new string object. 
   In a loop of 10,000 iterations, this is deadly. Use Buffers instead.

    b = buffer(2048.0) # Pre-allocate 2KB
    for i = 1.0 <= 1000.0 do
        buf_write(b, "Line number: ", i, "\n")
    end
    final_text = buf_string(b)
    buf_clear(b) # Ready for reuse

VII. GAME ENGINE INTEGRATION (ECS & CHAINING)
===============================================================================

Neutralis is designed for Entity-Component Systems. It uses a "Chaining" 
syntax where the `+` operator acts as a pipe for entity commands.

    # Create an NPC and apply transformations
    npc = create()
    npc + set_pos(100.0, 200.0) + rotate(45.0) + scale(1.5) + set_color("blue")
    
    # Commands like rotate() actually return a command tuple:
    # rotate(45.0) -> ["cmd_rotate", 45.0]
    
    # Moving with physics
    apply_force(npc, vec2(10.0, 0.0))
    
    # Visual Debugging
    draw_debug_circle(get_pos(npc), 50.0)

    # Modifier System
    add_modifier(npc, "burning")
    if has_modifier(npc, "burning") do
        say("System", "The NPC is on fire!")
    end

1. A REUSABLE TIMER CLASS (Using Dicts)
------------------------------------------------------------
    create_timer(duration) do
        t = dict()
        t.start = time()
        t.duration = duration
        t.is_expired() do
            return (time() - t.start) >= t.duration
        end
        return t
    end

    my_timer = create_timer(5.0)
    while my_timer.is_expired() == false do
        # Wait...
    end
    print("Time is up!")

3. CALCULATING DISTANCE BETWEEN VECTORS
------------------------------------------------------------
    # Built-in distance() exists, but here is how it works manually:
    v_dist(a, b) do
        dx = b.x - a.x
        dy = b.y - a.y
        return sin(dx*dx + dy*dy) # (using sin as placeholder for sqrt in this logic)
    end

IX. WARNINGS AND COMMON ERRORS (MANDATORY READING)
===============================================================================

⚠️ ERROR 1: THE TUPLE INDEXING TRAP
Most languages use 0-indexing. Neutralis uses 1-indexing for TUPLES 
but 0-indexing for STRING SUBSTRINGS.

    arr = tuple("A", "B")
    print(arr[1.0]) # "A"
    
    s = "AB"
    print(str_sub(s, 0.0, 1.0)) # "A"

⚠️ ERROR 2: FORGOTTEN END IN INLINE FUNCTIONS
Even single-line functions MUST close with `end`.

    BAD:  sq(x) = x * x
    GOOD: sq(x) = x * x end

⚠️ ERROR 3: DICT KEY OVERHEAD
Never use Dictionaries as Arrays. 

    BAD:  d = dict() d["1"] = "x"  # Forces string conversion + hash
    GOOD: t = tuple("x")          # Direct memory access

⚠️ ERROR 4: CALLING NIL
If you try to call a variable that contains `nil` as a function, 
the VM will crash.

    # UNSAFE
    my_callback() 
    
    # SAFE
    if check_null(my_callback) == false do
        my_callback()
    end


* VM Type: Register-based. Provides higher performance by reducing memory access.
* Value Representation: 64-bit NaN Boxing. 
  - Pointers use the lower 48 bits.
  - Floats are native IEEE-754.
  - Tags: Nil (1), False (2), True (3).
* Garbage Collector: Non-compacting Mark-and-Sweep. Fast and predictable.
* Hidden Classes: Dictionaries that share the same keys in the same 
  order share a "Shape". This allows the VM to memorize the memory 
  offset of a property, achieving C-like struct access speeds.

XII. FAQ
===============================================================================

Q: Why is my loop running so slowly?
A: Check if you are doing `print()` inside the loop or frequent 
   string allocations. IO and Allocation are the slowest operations.

Q: How do I load external libraries?
A: Put your `.neu` files in `C:\NeuLibs\` and use `call("filename")`. 
   Note: `call` runs the code in the global scope of the current VM.

Q: Can I catch exceptions?
A: Neutralis v2.0.2 does not support `try/catch`. Most errors are 
   fatal to the current script to ensure engine stability. Use 
   `assert()` to validate data early.

Q: Is there a maximum stack depth?
A: Yes, the stack is limited to 1024 slots for safety. Deep recursion 
   might trigger a stack overflow.
